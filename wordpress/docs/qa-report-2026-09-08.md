## Payment safety verification

Hermetic server/browser tests prove that TBT Core fails closed:

- Square is disabled unless the enable setting is explicitly truthy and all
  required credentials are available;
- a disabled endpoint returns `503` without making an outbound Square request;
- only an exact Square `COMPLETED` status is treated as payment success;
- `PENDING`, `APPROVED`, and missing statuses return `payment_unconfirmed`,
  create no confirmed deposit, and never show “Deposit Received” in the browser;
- idempotent retry and ambiguous-network recovery remain covered.

Square remains deliberately disabled on staging. No card was tokenized and no
payment or charge was attempted during this release. Before live payment QA,
remove the production credentials, install and validate sandbox credentials,
set `SQUARE_ENVIRONMENT=sandbox`, confirm the endpoint remains disabled, and
only then explicitly enable the sandbox test.
